Project Evidence Graph

Connect requirements, decisions, mappings, interfaces, tests, defects, changes, and evidence into a graph so traceability matrices, coverage, quality gates, impact reports, and assurance packs become generated views instead of manually maintained truth.

Coverage is useful only if the evidence is current enough and strong enough for the risk being claimed as assured.

Why it exists

Project rationale disappears across Jira, GitHub, ALM, documents, mappings, tests, defects, and evidence folders. A traceability spreadsheet can show a snapshot, but it rarely remains queryable or trustworthy.

01

Trace the rationale

Explicit links let teams move from requirement to implementation, test, defect, change, or evidence without fuzzy matching.

02

Measure assurance

Coverage can account for evidence freshness and risk weights, revealing critical uncovered requirements that raw percentages hide.

03

Generate the matrix

Traceability matrices, quality gates, impact views, and evidence packs are outputs of the graph, so the graph can be validated and reused.

Use the sources teams already have

Adapters keep vendor-specific exports at the boundary while canonical artifact IDs and explicit references keep the graph deterministic. The public synthetic case includes a generated assurance review and lifecycle decision.

Import without invented links

CSV manifests, saved GitHub Issues/PR JSON, Jira exports, and profile-driven work-item JSON can be normalized. Unresolved external references remain diagnostics instead of being silently connected.

Not a replacement for Jira, GitHub, ALM, or a document repository. It is a traceability and assurance layer across those artifacts.

Implemented handoffs

Three producer contracts are imported today. Stable references and provenance survive; attachment to a project requirement still needs an explicit project-owned bridge.

Reconciliation as Code →Import observed reconciliation runs and checks with producer fingerprints retained.Cutover Graph →Import fail-closed checkpoint assurance from the producer artifact index.Data Relationship Map →Import observed relationship evidence and producer-owned policy findings.
Agent entry point

Agents should cite the path to the claim.

The graph makes it possible for an agent to answer “why do we believe this requirement is covered?” with exact artifact links, evidence age, lifecycle state, and risk context instead of a document summary.

TRACE

Use explicit references

ASSURE

Check currency and lifecycle

Report stale-by-time and stale-by-change evidence separately, and keep superseded evidence visible but inactive.
